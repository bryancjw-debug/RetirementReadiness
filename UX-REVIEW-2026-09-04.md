## Limits and next checks

Browser checks use emulated dimensions, not physical iOS/Android devices. Real-device
keyboard and assistive-technology testing remain useful. This is not a formal WCAG
certification or complete security audit. Quiz drafts store questionnaire answers,
not a synchronised account or every later edit in the detailed results editor.
Draft validation rejects malformed shapes and non-finite values; future import work
must add a dedicated semantic schema, enumerations and field-specific range checks.

## Linking Common Cents and RetirementReadiness

Recommended: keep both apps independent and offer an optional, reviewed one-way
snapshot from Common Cents. Do not replace its retirement overview or automatically
write RetirementReadiness scenarios back to the original plan.

1. Define a versioned mapping for overlapping data, currency/base year, owner,
   assumptions and source date. Explain unsupported items before import.
2. Establish parity fixtures: different retirement/payout ages, mortgage OA use,
   insurance costs, self-employment, property sales and two-person ownership.
3. Start with explicit export/import and a preview of what will be used or omitted.
4. Only then add a consent-based direct handoff with verified sender/source and
   schema. Keep financial data out of URL queries and fragments.
5. Consider sharing calculation modules only after reconciling model differences.

Critical mappings: do not turn gross salary into investable savings; do not count
shared assets twice; distinguish dividend yield from total return; preserve cash
commitments and CPF housing refunds on property sale. Individual CPF/SRS accounts
must remain person-owned. Silent simplification would produce convincing but
inconsistent retirement results.

Both GitHub Pages apps currently use the same protocol/host/port, so different paths
are not browser-storage security boundaries. Namespaced draft keys avoid accidental
collisions, not cross-app access. Do not make shared localStorage the integration API.
